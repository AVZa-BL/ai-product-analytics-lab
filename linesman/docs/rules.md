# Rule catalogue

Generated from the rule code by `python -m linesman.rules.docs`. Do not edit this file by hand:
a test fails if it differs from the generated text. To change a rule, change it in
`src/linesman/rules/` and regenerate.

A **rule** looks at one validated plan and either finds nothing or raises one **finding**. Each
finding carries the rule's ID and severity, the evidence that triggered it, why it matters,
what to do, and its references. The same plan always gives the same findings.

| Severity | Effect on the review |
| --- | --- |
| blocker | The recommendation is `revise` and `linesman review-plan` exits with status 1. |
| warning | Reported; the recommendation stays `proceed`. |
| info | Reported; the recommendation stays `proceed`. |

Linesman is advisory. A recommendation of `proceed` means the plan raised none of the
objections below, not that the tracking is correct: Linesman reads the plan, never the data
the product actually sends.


## Naming

### NAM-001: Event name does not follow object_action

- **Severity:** warning
- **Fires when:** An event name is not at least two lowercase words joined by underscores.
- **Why it matters:** Names such as 'click' or 'CheckoutStarted' cannot be searched, grouped or governed consistently. A single convention is what lets a query select every event about one object, and keeps two spellings of one event from splitting its counts.
- **What to do:** Rename the event to object_action in snake_case, for example checkout_started. Deprecate the old name instead of reusing it.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### NAM-002: Property name is not snake_case

- **Severity:** warning
- **Fires when:** A property name is not lowercase words joined by underscores.
- **Why it matters:** Warehouses fold case differently, so 'planId' and 'plan_id' can become two columns or one, depending on the destination. A fixed style removes the ambiguity.
- **What to do:** Rename the property to snake_case, for example plan_id.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).



## Schema

### SCH-001: Same property name has different types on different events

- **Severity:** blocker
- **Fires when:** Two events declare a property with the same name but a different type.
- **Why it matters:** A property that is a string on one event and a number on another cannot be stored in one warehouse column, so loads fail or silently coerce, and joins across events give wrong results.
- **What to do:** Give the property one type everywhere, or rename one of them if they mean different things.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### SCH-002: Enum property declares no allowed values

- **Severity:** warning
- **Fires when:** A property of type enum has no allowed_values.
- **Why it matters:** Without a closed list, every typo or new spelling becomes a new category, and a funnel split by that property silently loses rows.
- **What to do:** List every permitted value in allowed_values, or change the type to string.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### SCH-003: Event cannot be tied to a user or device

- **Severity:** blocker
- **Fires when:** A planned or active event has no required property named in identity_keys.
- **Why it matters:** An event that does not say who or which device produced it cannot be counted per user, joined to other events, or used in any retention or conversion metric.
- **What to do:** Add one of the identity_keys to the event as a required property, or set it once globally and list it on every event.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).



## Documentation

### DOC-001: Event has no description or trigger

- **Severity:** warning
- **Fires when:** A planned or active event lacks a description or a trigger.
- **Why it matters:** If nobody wrote down when the event fires, each analyst guesses, and the same event name ends up meaning different things in different dashboards.
- **What to do:** Add a description (what it means) and a trigger (the exact user or system action that emits it).

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### DOC-002: Event has no owner

- **Severity:** warning
- **Fires when:** A planned or active event has no owner and the plan has no default owner.
- **Why it matters:** When an event breaks or its meaning must change, someone has to be asked. Without an owner the question has no answer, and broken events stay broken.
- **What to do:** Set the event's owner, or set a plan-level owner that covers every event.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).



## Governance

### GOV-001: Property name suggests personal data but is not marked pii

- **Severity:** blocker
- **Fires when:** A property is not marked pii: true and its name contains a personal-data word such as email, phone, address, ip, ssn, password, passport, dob, birthdate or surname, or a pair such as first_name or full_name.
- **Why it matters:** Personal data sent to analytics without a recorded decision is a privacy risk and a compliance question (data minimisation). The check is by name, so it can be wrong in both directions: it will miss a personal value with an innocent name.
- **What to do:** If the property holds personal data, set pii: true and record the lawful basis outside this plan, or stop sending it. If it does not, rename it so it is not mistaken for personal data.

- **References:**
  - Regulation (EU) 2016/679 (GDPR): Art. 4(1) personal data; Art. 5(1)(c) data minimisation.



## Coverage

### COV-001: Metric depends on an event the plan does not define

- **Severity:** blocker
- **Fires when:** A metric lists an event name that is not declared in events.
- **Why it matters:** A metric built on an event nobody tracks will read zero or stay empty, and the gap looks like a business result instead of a tracking hole.
- **What to do:** Define the event in events, or correct the name in the metric.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### COV-002: Metric depends on a deprecated event

- **Severity:** blocker
- **Fires when:** A metric lists an event whose status is deprecated.
- **Why it matters:** A deprecated event stops arriving. A metric still reading it will decay toward zero and be mistaken for a real decline.
- **What to do:** Point the metric at the replacement event, then retire the old one.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### COV-003: Metric depends on an event that is only planned

- **Severity:** warning
- **Fires when:** A metric lists an event whose status is planned.
- **Why it matters:** Until the event ships, the metric computes on partial or no data, and its history will have a break at the release date.
- **What to do:** Mark the metric as not ready until the event is active, or document the start date in the metric definition.

- **References:**
  - Kohavi, Tang, Xu. Trustworthy Online Controlled Experiments. Cambridge University Press, 2020 (chapter on instrumentation).


### COV-004: Active event is used by no metric

- **Severity:** info
- **Fires when:** The plan declares metrics and an active event appears in none of them.
- **Why it matters:** An event nobody reads still costs volume, maintenance and privacy exposure. It is either missing from a metric that should use it, or not worth collecting.
- **What to do:** Connect the event to a metric, or deprecate it.

- **References:**
  - Regulation (EU) 2016/679 (GDPR): Art. 4(1) personal data; Art. 5(1)(c) data minimisation.
