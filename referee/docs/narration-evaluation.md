What `--first-score` checked before it routed the held-out half:

- That the freeze commit is an ancestor of HEAD. The commit is looked up from HEAD, so on a real repository this is true by construction: the test guards a malformed answer only, and does not show that the commit is on main.
- That each frozen file other than the two held-out files equals its content at the freeze commit (`git show`).
- That the two held-out files (the questions and their brief) equal their pins in `pins.json` in the working tree. That is not a comparison with git.
- That every `referee.narration` module the process loaded is a frozen file of this tree, that `git status` listed nothing, untracked files included, and that no score file existed, so the first score is taken once.

It did not compare the digests inside `router_freeze.json` with the files; the freeze test in the default test run does.

A trigger word matches as a whole word after the router's own normalisation and reading of the question: no stem, no wildcard, no folding of look-alike letters. The fifteen words were committed with the router by step N5, before the half was scored; the repository does not record how they were chosen. *Intent keywords*: a question is answered if any of the router's intent patterns matches, else refused. `docs/grounding-study.md` measures what a closed-vocabulary checker accepts over enumerations of short texts: a checker's acceptance space, not what a model can or cannot do. Its figures, as `docs/grounding-study.json` states them: 0 of the 81 catalogue sentences contain none of the study's loaded words under its full list and 69 under the digits-only ablation, and the checker admitted 0 of 28 hand-written harmful probes under the full list (9 and 26 of 28 under the qualifiers-and-digits and digits-only ablations) (docs/grounding-study.md).

## Known gaps, and what is not verified

The known gaps are those of design section 24.13; this report adds none to the list of 24.13. Those that bear on the figures above:

- The held-out half is a procedure, not a technical barrier, and its questions, labels and reviews come from one kind of agent. The counts are agreement with an agent-authored taxonomy, not recall on real users' phrasing.
- Three questions per refusal category and five per intent (the sizes of design 24.10) rest on very little; no per-category figure should be read as a rate.
- The router is not injection-proof and its twelve categories are not complete. A question answered when it should have been refused gets the fixed page, which prints every finding.

Not verified: the model path has never been run with a model. Nothing here was run on macOS. That a page is byte-identical between machines is not checked until CI runs it.

## Reproduce

From `referee/`, with `src` and `tests` on `PYTHONPATH`:

- `python tests/narration_evaluation.py` prints the current score beside the first; it refuses until the first score exists.
- `python tests/narration_evaluation.py --first-score` takes the first score, once.
- `python tests/narration_evaluation.py --write` writes these two documents.
